# Server-side rendering

<Lede>
  To stream a styled document, route motif's generated CSS through `SSRStyleCollector` and inject
  the result into the response. Two patterns: a synchronous one for `renderToString`, and a registry
  component for streaming SSR.
</Lede>

<ArticleMeta />

## Sync render-to-string

For Express / Fastify / Vite SSR / any server using `renderToString`, create a collector per
request, run the render inside it, and embed the captured `<style>` block in the head.

<CodeBlock lang="tsx" filename="server.tsx" code={`import { renderToString } from 'react-dom/server';
import { SSRStyleCollector } from 'usemotif';
import { App } from './App';

export function render() {
  const collector = new SSRStyleCollector();

  const body = collector.collect(() => renderToString(<App />));
  const styleTag = collector.getStyleTag();

  return \`<!doctype html>
<html>
  <head>
    \${styleTag}
  </head>
  <body><div id="root">\${body}</div></body>
</html>\`;
}`} />

The collected rules ship as a `<style data-motif-ssr>` block. On the client, motif's runtime
reads the marker, seeds its dedup set, and skips re-injecting any rule the server already emitted.
No flash; no double work.

## Streaming SSR and RSC

Streaming renderers (`renderToReadableStream`, `renderToPipeableStream`) interleave async work
across requests. The default sync collector is module-scoped, which corrupts under concurrency -
two requests share the same active pointer.

The fix is one import at app startup:

<CodeBlock lang="ts" code={`// server-entry.ts (or similar)
import '@usemotif/react/server';`} />

That module registers an `AsyncLocalStorage`-backed storage for the active collector. Each
request sees its own collector; concurrent requests do not collide.

After the import, the rest of the API is the same: create a collector per request, route the
render through `collector.collect(...)` (or via `CollectorContext`, below), and emit the style tag.

## Next.js App Router

App Router renders in chunks and re-flushes the head as it streams. Motif ships no built-in
provider for this - the integration is a fifteen-line registry that lives in your app.

<CodeBlock lang="tsx" filename="app/motif-style-registry.tsx" code={`'use client';

import { useState, type ReactNode } from 'react';
import { useServerInsertedHTML } from 'next/navigation';
import { CollectorContext, SSRStyleCollector } from 'usemotif';

export function MotifStyleRegistry({ children }: { children: ReactNode }) {
  const [collector] = useState(() => new SSRStyleCollector());

  useServerInsertedHTML(() => {
    const css = collector.getCss();
    if (css.length === 0) return null;
    collector._drain();
    return <style data-motif-ssr dangerouslySetInnerHTML={{ __html: css }} />;
  });

  if (typeof window !== 'undefined') {
    return <>{children}</>;
  }

  return <CollectorContext.Provider value={collector}>{children}</CollectorContext.Provider>;
}`} />

Mount it inside `<body>` in your root layout, with the theme provider underneath:

<CodeBlock lang="tsx" filename="app/layout.tsx" code={`import { ThemeProvider } from 'usemotif';
import { MotifStyleRegistry } from './motif-style-registry';
import { lightTheme, darkTheme } from './theme';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <MotifStyleRegistry>
          <ThemeProvider themes={[lightTheme, darkTheme]} active="light">
            {children}
          </ThemeProvider>
        </MotifStyleRegistry>
      </body>
    </html>
  );
}`} />

`useServerInsertedHTML` fires on every flush; `_drain()` clears the collector's emitted rules so
each flush only includes what is new. The dedup set stays populated, so two flushes never emit the
same class twice.

## React Router 7

React Router's framework mode streams through a Node `entry.server`. Give each request its own
collector, provide it with `CollectorContext`, and pipe React's stream through
`motifStyleStream`, which writes the collected CSS into the HTML as it goes: into `<head>` with
the shell, then ahead of each later chunk, so a Suspense boundary's styles arrive before its
content.

<CodeBlock lang="tsx" code={`// app/entry.server.tsx
import { PassThrough } from 'node:stream';
import { createReadableStreamFromReadable } from '@react-router/node';
import { CollectorContext } from '@usemotif/react';
import { motifStyleStream, SSRStyleCollector } from '@usemotif/react/server';
import { isbot } from 'isbot';
import { renderToPipeableStream } from 'react-dom/server';
import { ServerRouter, type EntryContext } from 'react-router';

export const streamTimeout = 5000;

export default function handleRequest(
  request: Request,
  status: number,
  headers: Headers,
  context: EntryContext,
) {
  return new Promise<Response>((resolve, reject) => {
    const collector = new SSRStyleCollector();
    const ready = isbot(request.headers.get('user-agent') ?? '') ? 'onAllReady' : 'onShellReady';
    const { pipe, abort } = renderToPipeableStream(
      <CollectorContext.Provider value={collector}>
        <ServerRouter context={context} url={request.url} />
      </CollectorContext.Provider>,
      {
        [ready]() {
          const body = new PassThrough();
          headers.set('Content-Type', 'text/html');
          resolve(new Response(createReadableStreamFromReadable(body), { headers, status }));
          pipe(motifStyleStream(collector)).pipe(body);
        },
        onShellError: reject,
      },
    );
    setTimeout(abort, streamTimeout + 1000);
  });
}`} />

Put `ThemeProvider` in the root route's `Layout`, inside `<body>`. `apps/ssr-react-router` in
the repository is this setup with a deferred loader, and CI serves its production build and checks
the streamed HTML and the hydrated page on every change.

## Primitives in Server Components

Everything from `@usemotif/react` is a client component, so it renders on the server but ships its
code to the browser too. For layout that never needs the client, import the primitives from
`@usemotif/react/rsc` in a Server Component instead:

<CodeBlock lang="tsx" filename="app/page.tsx" code={`import { Box, HStack, Text } from '@usemotif/react/rsc';

export default function Page() {
  return (
    <Box p={{ base: '$4', md: '$8' }}>
      <HStack gap="$3" _hover={{ opacity: 0.9 }}>
        <Text lines={1}>Rendered on the server</Text>
      </HStack>
    </Box>
  );
}`} />

`Box`, `Stack`, `HStack`, `VStack` and `Text` from there resolve their styles to class names on the
server. Their CSS ships as React's hoisted `<style precedence>`, which React deduplicates and moves
into the document head as the page streams, so they need neither the style registry nor a client
boundary. Tokens become CSS variables, so the theme reaches them through the cascade from the
`ThemeProvider` above.

A prop that needs the client hands that element to the client primitive: event handlers, `ref`,
`enterStyle`, `exitStyle`, `layout`, `drag`, motion values and `Stack`'s `stagger`. A
`ThemeProvider` `cssLayer` is client context, so it doesn't reach the server primitives.

## Hydration without a flash

Three things to confirm before shipping:

1. **The `<style data-motif-ssr>` block is in the streamed HTML.** Open `view-source:` on a
   server-rendered page; the block should appear in `<head>` (sync) or near the top of `<body>`
   (App Router). If it is not there, the collector ran but nothing was injected - check that the
   collector is in scope when the components render.
2. **The theme variables block is present.** `<ThemeProvider>` emits a `<style data-motif-themes>`
   block of its own. Both blocks need to be in the document on first paint, or token references
   resolve to the browser default during hydration.
3. **`prefers-color-scheme` lands the right theme.** If you persist the user's choice in
   `localStorage` or a cookie, set `data-theme` on `<html>` from the server (cookie) or via a
   pre-paint script in the document head (localStorage). Otherwise the first paint is whichever
   theme is `active` on the provider.

<Callout variant="tip" title="Next.js Pages Router">
  The Pages Router (`pages/_document.tsx`) uses a different injection point. Wrap the render in
  `collector.collect(...)` from `getInitialProps` and stamp `collector.getStyleTag()` into the
  `Document` head. The async-storage import is still required - Next streams.
</Callout>
