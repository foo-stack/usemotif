# UI kit

<Lede>
  Where [recipes](/recipes/component-recipes) give you styling data and the [headless](/headless)
  components give you behaviour, `@usemotif/ui` gives you the finished components - already themed,
  already interactive. Import one and render it; there is no `styled()` call to make first.
</Lede>

<ArticleMeta />

## What it is

A leaf package of ready components. Each one is assembled from three layers you can also use on
their own:

- **Primitives** from `usemotif` - `Box`, `Text`, `Avatar`, and the rest of the
  [components](/components).
- **Headless behaviours** from `@usemotif/headless` - focus, keyboard, and ARIA wiring for the
  interactive components.
- **Recipes** from `@usemotif/recipes` - the `styled()` configs for Card, Badge, Alert, Banner,
  Chip, and Stat.

Colours, spacing, and radii resolve from the active theme's tokens, so every kit component
re-themes in light and dark with the rest of your app.

## Install

<CodeBlock lang="bash" code={`yarn add @usemotif/ui`} />

`usemotif`, `@usemotif/headless`, and `react` are peer dependencies.

<CodeBlock lang="tsx" code={`import { Card, Badge, Alert } from '@usemotif/ui';`} />

<Callout variant="info" title="Pay only for what you import">
  The kit is code-split per component. Importing `Card` pulls its primitives and recipe, not the
  `@usemotif/headless` dependency an overlay component carries. A display-only app never bundles the
  overlay layer.
</Callout>

<Callout variant="warning" title="Web only, for now">
  The kit targets the web today. The package ships no `.native.tsx` variants, so its components are
  not yet built for React Native. The primitives and headless behaviours it is made from are
  cross-platform.
</Callout>

## On React Native

Every kit component renders on React Native from the same import: Metro resolves the
package's `react-native` export condition to a native build. That covers the display components:
Card (with its parts), Badge, Alert, Banner, Chip, Spinner, Skeleton, Progress, ProgressCircle,
Button and TextField.

It covers the overlays: Modal, AlertDialog, Drawer, Sheet, Popover, Tooltip, HoverCard, Menu,
ContextMenu and the Toaster, over the headless components' native versions, with the same tokens on
their surfaces.

On native, text inside any of these sits in `Text`, carrying the colour and size the web element
would pass down, and ProgressCircle draws with `react-native-svg`. TextField renders the platform
`Input`, sized from the recipe. Hover and keyboard-focus styles have no native equivalent.

The form controls render on native as well. Most take the same props on both platforms. Checkbox,
Switch, Radio and RadioGroup are the exception: on the web they are real `<input>` elements with
`checked` and `onChange`, and on native they take their headless twins' `value`, `defaultValue` and
`onValueChange`, as the platform controls do. Calendar and DatePicker drop their web surface styles
on native.

The navigation and disclosure components complete the set: Tabs, Accordion, Collapsible,
Breadcrumb, Pagination, Stepper, Toolbar, NavigationMenu, TreeView and CommandPalette, along with
Separator, Stat, EmptyState, Timeline and AvatarGroup. Links in Breadcrumb and NavigationMenu open
with `Linking`, and Pagination leaves out its page-size select, which is a web `<select>`.
