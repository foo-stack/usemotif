# Chip

<Lede>
  Chip is a compact tag, like a Badge built for input affordances: it can lead with an icon and end
  with a `×` button that removes it.
</Lede>

<ArticleMeta />

## What it is

A `Box` styled by the `chipRecipe` from `@usemotif/recipes`. The recipe adjusts the padding when
an `icon` is present and when the chip is removable, so the content stays balanced either way.

Setting `onRemove` renders a `×` button labelled "Remove" that calls it; `removeLabel` renames it,
which matters when several chips sit together ("Remove react"). Chip does not remove itself; your
state owns the list of chips.

## Install

<CodeBlock lang="bash" code={`yarn add @usemotif/ui`} />

<CodeBlock lang="tsx" code={`import { Chip } from '@usemotif/ui';`} />

## Usage

<CodeBlock lang="tsx" code={`import { useState } from 'react';
import { Chip } from '@usemotif/ui';
import { HStack } from 'usemotif';

function Filters() {
  const [tags, setTags] = useState(['react', 'typescript']);
  return (
    <HStack gap="$space.2">
      {tags.map((tag) => (
        <Chip key={tag} onRemove={() => setTags((t) => t.filter((x) => x !== tag))}>
          {tag}
        </Chip>
      ))}
    </HStack>
  );
}`} />

A primary chip with an icon:

<CodeBlock lang="tsx" code={`import { Chip } from '@usemotif/ui';

<Chip intent="primary" icon={<TagIcon />}>
  Featured
</Chip>`} />

Filter chips. Give a chip `selected` (or `defaultSelected`) and `onSelectedChange` and its label
becomes a toggle button with `aria-pressed`, filled with the primary colour while selected. A
remove button, if there is one, stays a separate target:

<CodeBlock lang="tsx" code={`import { Chip } from '@usemotif/ui';
import { HStack } from 'usemotif';

<HStack gap="$space.2" role="group" aria-label="Filter by status">
  {STATUSES.map((status) => (
    <Chip
      key={status}
      selected={active.has(status)}
      onSelectedChange={(on) => toggleStatus(status, on)}
    >
      {status}
    </Chip>
  ))}
</HStack>`} />
