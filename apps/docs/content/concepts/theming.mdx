# Theming

<Lede>
  Tokens describe the values. Theming is how a particular tree becomes the active one - and how a
  subtree opts into a different one without a render storm.
</Lede>

<ArticleMeta />

## A theme is data

A theme is a plain object: a `name` plus a token tree. Two themes - `light` and `dark` - are
typically the whole story.

<CodeBlock lang="tsx" code={`import { createTheme } from 'usemotif';

export const lightTheme = createTheme({
  name: 'light',
  tokens: {
    colors: {
      ink: '#1C1917',
      paper: '#FBF7F2',
      surface: { base: '$colors.paper', inverse: '$colors.ink' },
      text: { default: '$colors.ink', inverse: '$colors.paper' },
    },
  },
});

export const darkTheme = createTheme({
  name: 'dark',
  tokens: {
    colors: {
      ink: '#1C1917',
      paper: '#FBF7F2',
      surface: { base: '$colors.ink', inverse: '$colors.paper' },
      text: { default: '$colors.paper', inverse: '$colors.ink' },
    },
  },
});`} />

Both themes share the same primitive layer (`ink`, `paper`). Only the semantic layer (`surface`,
`text`) differs. Components reference the semantic paths and the right values arrive.

### A palette from one colour

`generatePalette` in `@usemotif/tokens` builds a 12-step light scale and a 12-step dark scale from
one brand colour, spaced evenly in OKLCH:

<CodeBlock lang="ts" code={`import { generatePalette } from '@usemotif/tokens';

const brand = generatePalette('#7c3aed');
// brand.light[9] === '#7c3aed', brand.dark[9] === '#7c3aed'

export const lightTheme = createTheme({
  name: 'light',
  tokens: {
    colors: {
      brand: brand.light,
      action: { primary: { bg: '$colors.brand.9' } },
      text: { accent: '$colors.brand.11' },
    },
  },
});`} />

| Steps | Use |
| --- | --- |
| 1, 2 | App and subtle backgrounds |
| 3 to 5 | Component backgrounds: rest, hover, pressed |
| 6 to 8 | Borders, from subtle to strong |
| 9, 10 | The colour itself, and its hover |
| 11, 12 | Text, held to 4.5:1 and 7:1 contrast against step 2 |

Hue stays fixed. Chroma is reduced on any step that would fall outside sRGB, so every value is a
plain hex colour. A colour it cannot parse throws.

## ThemeProvider makes themes available

`<ThemeProvider>` does two things at the top of the tree:

1. Emits one `<style>` element containing the CSS-variable declarations for every theme it knows
   about, scoped per `[data-theme="<name>"]`.
2. Wraps its children in a `<div data-theme={active}>`.

<CodeBlock lang="tsx" code={`import { ThemeProvider } from 'usemotif';
import { lightTheme, darkTheme } from './theme';

export function App({ children }: { children: React.ReactNode }) {
  return (
    <ThemeProvider themes={[lightTheme, darkTheme]} active="light">
      {children}
    </ThemeProvider>
  );
}`} />

The `themes` prop is the catalogue: every theme that might be active. The `active` prop is the
current one. Pass both - the catalogue stays stable, and `active` is the only thing that changes
when the user toggles.

### Shadow roots and iframes

Styles in the main document's `<head>` don't reach a shadow root or an iframe's document. When a
tree renders into one, pass it as `styleTarget`, and motif adopts its CSS there as a constructable
stylesheet: the theme, every rule it emits at runtime for state, breakpoint and container styles,
and any server-rendered rules.

<CodeBlock lang="tsx" code={`const shadow = host.attachShadow({ mode: 'open' });

createRoot(shadow).render(
  <ThemeProvider themes={themes} active="light" styleTarget={shadow}>
    <Widget />
  </ThemeProvider>,
);

// An iframe: portal into its body and target its document.
createPortal(
  <ThemeProvider themes={themes} active="light" styleTarget={iframe.contentDocument}>
    <Preview />
  </ThemeProvider>,
  iframe.contentDocument.body,
);`} />

Inside an iframe, media-query breakpoints follow the iframe's width. Outside React,
`registerStyleTarget(target)` from `@usemotif/react` does the same and returns a function that
removes it.

## Switches are attribute swaps

Because every theme's CSS variables are already on the page, a theme switch is one of:

- **Web.** Set `data-theme="dark"` on the wrapper. The cascade picks up the dark block. No React
  re-render, no remount, no recomputation of styles.
- **Native.** Update the `active` prop. The provider re-reads from the in-memory token tree and
  components consuming `useTheme()` re-render.

The web path is the cheap one. Setting an attribute is a single DOM write; the browser handles
everything downstream. That is why a typical theme toggle reads from `document.documentElement`,
not from React state - the source of truth lives on the element, and the toggle just flips it.

## Nested themes compose

A subtree can ask for a different theme without affecting the rest of the page. `<Theme>` sets a
new `data-theme` on its own wrapper.

<CodeBlock lang="tsx" code={`import { Theme } from 'usemotif';

<ThemeProvider themes={[light, dark]} active="light">
  <Box bg="$colors.surface.base">{/* light surface */}</Box>
  <Theme name="dark">
    <Box bg="$colors.surface.base">{/* dark surface */}</Box>
  </Theme>
</ThemeProvider>;`} />

Themes also chain. Inside a `dark` provider, `<Theme name="red">` composes the names into a
`dark_red` lookup. If `dark_red` is in the `themes` array, that theme wins; otherwise motif falls
back to the inner name (`red`), and then the parent's active name. Pre-register the combinations
you care about and they activate automatically.

## Same model, two renderers

`<ThemeProvider>` is a thin shell over the same tree on both platforms. On web, the tree becomes
CSS variables and the `data-theme` attribute is the activation switch. On native, the tree lives
in context and the runtime resolver reads from it directly.

The component code does not branch. `<Box bg="$colors.surface.base" />` is the same on either
side; the platform decides how `$colors.surface.base` becomes a paint.
