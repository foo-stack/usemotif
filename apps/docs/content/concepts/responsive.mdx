# Responsive

<Lede>
  Every style prop accepts more than one value. Pass an object keyed by breakpoint, a positional
  array, or a compact string - viewport queries and container queries fall out of the same shape.
</Lede>

<ArticleMeta />

## Responsive props are values

A literal value applies unconditionally. A responsive object spreads the same prop across
breakpoints - `base` for the unconditional case, named keys for each breakpoint upward.

<CodeBlock lang="tsx" code={`<Box
  bg={{ base: '$colors.surface.muted', md: '$colors.surface.base' }}
  p={{ base: '$space.3', md: '$space.4', lg: '$space.6' }}
/>`} />

Motif resolves each slot, emits one rule per breakpoint, and hashes the lot into a generated class.
The `base` slot lands on inline style; everything else becomes a media query in a stylesheet
injected once and shared across the page.

## Three forms for the same value

The object form is the long version. Two shorter ones exist for places where they read more
clearly.

The **array form** is positional: `[base, sm, md, lg, xl, '2xl']`. Trailing slots are optional;
`undefined` slots are dropped.

<CodeBlock lang="tsx" code={`<Box p={['$space.3', '$space.4', '$space.6']} />
//      base         sm           md`} />

The **DSL form** is a single string of `<key>:<value>` pairs separated by whitespace.

<CodeBlock lang="tsx" code={`<Box gap="base:2 md:4 lg:8" />`} />

Numbers in the DSL are coerced when they parse cleanly. `"md:8"` becomes `{ md: 8 }`; `"md:8px"`
stays a string. Use whichever reads best at the call site - they all compile to the same rules.

## Mobile-first breakpoints

The default breakpoint set is Tailwind-aligned and mobile-first:

| Name   | Min-width |
| ------ | --------- |
| `base` | 0         |
| `sm`   | 640px     |
| `md`   | 768px     |
| `lg`   | 1024px    |
| `xl`   | 1280px    |
| `2xl`  | 1536px    |

Each rule is a `min-width` query. A value at `md` applies from 768px upward and stays applied
until something at `lg` or `xl` overrides it. Write the smallest-screen value at `base` and let
larger screens add to it.

These widths are the defaults; you can [retune them](/guides/configuring-breakpoints) to your
design system. The five names stay fixed - only the pixel values change.

## Container queries scope to a parent

Some components should respond to their container's width, not the viewport's. A card in a sidebar
is the same component as a card in the main column, but it has half the room. For those cases,
prefix the breakpoint with `@`.

<CodeBlock lang="tsx" code={`<Box
  // matches the nearest ancestor that opted into container queries
  flexDirection={{ base: 'column', '@md': 'row' }}
  // matches a named container - \`<Box style={{ container: 'card / inline-size' }}>\`
  gap={{ base: '$space.2', '@card.md': '$space.4' }}
/>`} />

`@<bp>` binds to the nearest container ancestor. `@<name>.<bp>` binds to a container with that
name. Container queries don't replace media queries - they sit alongside them in the same object.

## User preferences are keys too

Beside the widths, a responsive value takes five keys for what the user has asked for:

<CodeBlock lang="tsx" code={`<Box
  bg={{ base: '$colors.surface.muted', '@contrast': '$colors.surface.base' }}
  borderWidth={{ base: 0, '@forcedColors': 1 }}
  display={{ base: 'flex', '@print': 'none' }}
  p={{ base: '$3', md: '$5', '@landscape': '$4' }}
/>`} />

| Key | Web | React Native |
| --- | --- | --- |
| `@contrast` | `@media (prefers-contrast: more)` | high text contrast (Android) or darker system colours (iOS), from `AccessibilityInfo` |
| `@forcedColors` | `@media (forced-colors: active)` | never |
| `@reducedTransparency` | `@media (prefers-reduced-transparency: reduce)` | reduce transparency (iOS), from `AccessibilityInfo` |
| `@print` | `@media print` | never |
| `@landscape` | `@media (orientation: landscape)` | the window is wider than it is tall |

A preference wins over every width rule, so `p={{ md: '$5', '@landscape': '$4' }}` is `$4` in
landscape at any width. On React Native the settings are read once for the app and followed as
they change, and components re-render when one does. The compiler extracts these keys like any
other, and `PREFERENCE_QUERIES` maps each key to its media query.

## One source, three queries

A responsive value is a description, not a query. Motif decides whether each slot becomes a media
rule, a container rule, or an inline style based on the slot's key. The component author writes
one shape; the platform decides how to enforce it.

That is also why the same prop accepts every form. Whether you reach for the object, the array,
or the DSL is a question of taste at the call site - none of them is faster, none is more
expressive than the others, and motif deduplicates the resulting CSS regardless.

## When a value isn't enough: `useMedia`

Responsive props cover the common case - one style value that changes by breakpoint. Sometimes the
branch is on something else: which component to render, a prop on a non-styled element, a count, a
piece of imperative logic. For those, read the breakpoints directly with `useMedia`.

<CodeBlock lang="tsx" code={`import { useMedia } from 'usemotif';

function Gallery() {
  const media = useMedia();
  const columns = media.xl ? 4 : media.md ? 2 : 1;
  return <Grid templateColumns={\`repeat(\${columns}, 1fr)\`} />;
}`} />

`useMedia()` returns a map of every breakpoint to whether the viewport is at least that wide -
`{ sm, md, lg, xl, '2xl' }` - using the same mobile-first min-width semantics as the props. The
scalar `useBreakpoint()` returns the single active band (`'base'`, `'sm'`, ...) when that reads more
naturally.

Both work the same on web and native (driven by `matchMedia`/resize on web, `Dimensions` on
native) and both are deliberately economical: a consumer re-renders **only when a breakpoint
boundary is crossed**, never on an in-between resize. On the server and the first client render
they assume a default width so hydration doesn't mismatch, then reconcile to the real width on
mount.

<Callout variant="warning" title="Prefer the prop syntax for style values">
  If the thing that changes is a single style value, use the responsive prop - it compiles to CSS
  and costs nothing at runtime. `useMedia` runs in JavaScript and re-renders the component on a
  breakpoint change, so reach for it only when a plain responsive value can't express the branch.
</Callout>
