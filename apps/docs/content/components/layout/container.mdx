# Container

<Lede>
  Container is a Box that registers itself as a CSS container. Descendants can then target it with
  `@<bp>` keys in any responsive prop - reflow on the container's width, not on the viewport's.
</Lede>

<ComponentDemoStrip demo="container" />

<ArticleMeta />

## What it is

A `<Box>` with `container-type` set. Most apps target one of two shapes - a `name`-less Container
so descendants address it implicitly with `@<bp>`, or a `name="card"` Container so descendants
target it explicitly with `@card.<bp>`. The two coexist; nested containers stay addressable.

## Install

`Container` is exported from `usemotif`. No separate install.

<CodeBlock lang="tsx" code={`import { Container } from 'usemotif';`} />

## Examples

Implicit container - single-Container case where descendants target with `@<bp>`:

<CodeBlock lang="tsx" code={`<Container>
  <Box p={{ base: '$2', '@md': '$4', '@lg': '$8' }}>
    Padding reflows on the container's width.
  </Box>
</Container>`} />

Named container - multiple containers nested, addressed by name:

<CodeBlock lang="tsx" code={`<Container name="card">
  <Heading fontSize={{ base: '$lg', '@card.md': '$xl' }}>
    Reflow only when the card grows.
  </Heading>
</Container>`} />

Sidebar list of cards, each card its own container:

<CodeBlock lang="tsx" code={`<Grid columns={{ base: 1, md: 2, lg: 3 }} gap="$4">
  {items.map((it) => (
    <Container key={it.id} name="card">
      <Box p={{ base: '$2', '@card.md': '$4' }}>
        <Heading>{it.title}</Heading>
        <Text>{it.body}</Text>
      </Box>
    </Container>
  ))}
</Grid>`} />

## Reading the width

`useContainerInfo()` returns the measured widths of the enclosing containers, for decisions a
style prop cannot make, such as rendering a different component:

<CodeBlock lang="tsx" code={`import { useContainerInfo } from 'usemotif';

function CardBody() {
  const { named } = useContainerInfo();
  return (named.get('card') ?? 0) >= 480 ? <WideLayout /> : <StackedLayout />;
}`} />

<CodeBlock lang="ts" code={`interface ContainerContextValue {
  readonly nearestWidth: number | null;           // innermost measured Container
  readonly named: ReadonlyMap<string, number>;    // each measured named ancestor
}`} />

A width is absent until the container is first measured, and always during server rendering, so
render something sensible for `null`. An inner container with the same name as an outer one
shadows it.

On web a container only measures while something below it calls the hook, through one
`ResizeObserver` that stops when the last reader unmounts. The width is the content box, the same
box the browser's container queries measure, so the hook and `@md` styling agree.

## Cross-platform notes

On web Container emits the `container-type` / `container-name` CSS properties, and container
queries resolve in the browser. React Native has no container queries, so Container measures
itself with `onLayout` and descendants resolve `@<bp>` and `@<name>.<bp>` keys against that width
in JavaScript. `useContainerInfo()` returns the same shape on both platforms.
