# TitleBar

<Lede>
  TitleBar replaces the OS title bar in a frameless desktop window. The bar drags the window, a
  `leading` and a `trailing` slot hold your own controls and stay clickable, and the bar keeps clear
  of the OS window buttons.
</Lede>

<ArticleMeta />

## Usage

<CodeBlock lang="tsx" code={`import { TitleBar } from 'usemotif';

<TitleBar
  title={document.title}
  px="$3"
  bg="$colors.surface.muted"
  leading={<IconButton aria-label="Menu" icon={Menu} onPress={openMenu} />}
  trailing={<IconButton aria-label="Share" icon={Share} onPress={share} />}
/>`} />

Give it the window's full width, at the top. `children` replaces the centred `title` with your own
content, such as tabs.

## Electron

Hide the OS title bar and turn on the controls overlay, which tells the page where the OS window
buttons sit:

<CodeBlock lang="js" filename="main.js" code={`new BrowserWindow({
  titleBarStyle: 'hidden',
  titleBarOverlay: true,
});`} />

The bar is an `app-region: drag` area and its slots are `no-drag`. Under the overlay it pads itself
by the overlay's `titlebar-area-x` and `titlebar-area-width`, so on macOS it starts after the
traffic lights and on Windows and Linux it stops before the caption buttons. Without an overlay the
padding is 0.

## Tauri

Set `"decorations": false` (or a transparent title bar on macOS) in `tauri.conf.json` and allow
`core:window:allow-start-dragging` in your capabilities. The bar and its title carry
`data-tauri-drag-region`; the slots don't, so they stay clickable.

## React Native desktop

On react-native-windows and react-native-macos, TitleBar lays out the same slots. React Native has
no drag-region API, so the window keeps dragging from the OS title bar there. The same component
renders on all of them, so shared screens don't branch on platform.
