# Combobox

<Lede>
  Combobox is a single-select with type-to-filter. An input narrows a listbox of options as the
  user types; the arrow keys and Enter pick one. It is the base Select, Search, and MultiSelect
  build on.
</Lede>

<ComponentDemoStrip demo="combobox" />

<ArticleMeta />

## What it is

A compound component. `Combobox.Root` holds the options, the selected value, the input text, and
the open state - every piece controllable or uncontrolled. `Combobox.Input` is the typeable
field; `Combobox.List` is the filtered, portalled listbox. Filtering defaults to a
case-insensitive substring match on each option's label; pass `filter` to override it.

## Install

<CodeBlock lang="bash" code={`yarn add @usemotif/headless`} />

<CodeBlock lang="tsx" code={`import { Combobox } from '@usemotif/headless';`} />

## Anatomy

<CodeBlock lang="tsx" code={`<Combobox.Root options={options} onValueChange={setValue}>
  <Combobox.Input placeholder="Search..." />
  <Combobox.List
    renderOption={(option, { highlighted }) => (
      <Row option={option} active={highlighted} />
    )}
  />
</Combobox.Root>`} />

### Combobox.Input

The typeable field. Pass a `placeholder`, or a single element child to use your own input -
Combobox clones it with the combobox ARIA wiring and the keyboard handlers.

## Options fetched as you type

`onInputValueChange` fires on every keystroke, so it is where a fetch starts. Pass the results as
`options` with `filter={false}`, so the built-in substring filter does not hide matches the
server ranked or matched loosely, and set `loading` while a request is in flight.

<CodeBlock lang="tsx" code={`const [query, setQuery] = useState('');
const { data = [], isFetching } = useSearch(query); // your fetch, debounced as you like

<Search.Root
  options={data}
  filter={false}
  loading={isFetching}
  onInputValueChange={setQuery}
>
  <Search.Input placeholder="Search docs" />
  <Search.List loadingMessage="Searching..." emptyMessage="No results" />
</Search.Root>`} />

While `loading` is set and there are no options, the list shows `loadingMessage` where the empty
message would go; options already on screen stay. On the web the listbox carries `aria-busy`
while loading. The same props work on React Native.

## Long lists

From 50 options the list renders only the rows in view, plus a few either side, with spacers
keeping the scrollbar true to the full list. The highlighted row always stays rendered: arrow
keys, Home and End scroll it into view, so `aria-activedescendant` never names a missing row. Each
row carries `aria-setsize` and `aria-posinset`, so assistive tech still announces "12 of 4000".

The rows must share one height. It is measured from the first row, or pass `itemHeight` to skip
the measurement. The listbox needs a bounded height to scroll in, such as a `maxHeight` in its
`style`. This applies to `Select.List`, `Search.List`, `MultiSelect.List`, and `Listbox` too. On
React Native the options sheet renders through `FlatList`, which virtualizes on its own.

## Keyboard

Arrow Down and Up move the highlight (Arrow Down also opens a closed listbox), Home and End jump
to the ends, Enter selects the highlighted option, Escape closes the listbox.

## Accessibility

Combobox implements the WAI-ARIA combobox pattern. The input is `role="combobox"` with
`aria-expanded`, `aria-controls`, `aria-autocomplete="list"`, and `aria-activedescendant`
tracking the highlighted row. The listbox is `role="listbox"`, each row `role="option"` with
`aria-selected`. Disabled options carry `aria-disabled` and are skipped on selection.
