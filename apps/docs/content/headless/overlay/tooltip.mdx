# Tooltip

<Lede>
  Tooltip shows a short text label on hover or keyboard focus. It binds to the trigger through
  `aria-describedby`, so a screen reader announces the label alongside the trigger's name.
</Lede>

<ComponentDemoStrip demo="tooltip" />

<ArticleMeta />

## What it is

A compound component for descriptive text attached to a control. It opens after `openDelay` on
hover or focus, closes after `closeDelay` when the pointer or focus leaves, and closes
immediately on Escape. `Tooltip.Content` renders into a [Portal](/components/utilities/portal)
with `role="tooltip"`.

Tooltip holds text and only text. The moment the content needs a link or a button, the component
is wrong - a hover affordance cannot be operated by keyboard or touch users. Reach for
[HoverCard](/headless/overlay/hover-card) or [Popover](/headless/overlay/popover) instead.

## API

### Tooltip.Provider

<ApiSignature
  name="Tooltip.Provider"
  status="stable"
  signature={`function Tooltip.Provider(props: TooltipProviderProps): JSX.Element`}
  params={[
    {
      name: 'skipDelayDuration',
      type: 'number',
      default: '300',
      description: 'How long after the last tooltip in the group closes the next one still opens at once, in ms.',
    },
  ]}
/>

Wrap a set of tooltips, such as a toolbar's, in one Provider. The first tooltip waits its
`openDelay`; once it is showing, moving to a neighbour opens that one at once and hides the first,
so the user can scan the row without waiting at each button. When no tooltip in the group has been
open for `skipDelayDuration`, the delay applies again. On React Native the Provider renders its
children unchanged, since native tooltips open on press.

### Tooltip.Arrow

<ApiSignature
  name="Tooltip.Arrow"
  status="stable"
  signature={`function Tooltip.Arrow(props: FloatingArrowProps): JSX.Element | null`}
  params={[
    { name: 'size', type: 'number', default: '8', description: 'Width of the square the arrow is cut from, in px.' },
    { name: 'borderColor', type: 'string', description: 'Draws the arrow\'s two outer edges in this colour, to continue a bordered surface.' },
    { name: 'borderWidth', type: 'number', default: '1', description: 'Border width with `borderColor`, in px.' },
    { name: 'style', type: 'CSSProperties', description: 'Style for the arrow, usually its `background`.' },
  ]}
/>

An arrow on the edge facing the trigger, pointing at the trigger's centre. It is a square turned 45
degrees and straddling the edge, so render it first inside `Tooltip.Content` with the surface's
background, and the surface covers its inner half. It moves to the other edge when the surface
flips, and stays on the trigger when the surface shifts along the viewport edge. It carries
`aria-hidden` and `data-side` (`top`, `bottom`, `left`, or `right`), for styling by side. On React
Native it renders nothing, since native overlays open as modals with no anchored edge.

## Accessibility

The tooltip binds to the trigger with `aria-describedby` while open, so its text is announced as
the trigger's description. Because the trigger must be focusable for the focus path to work, the
element inside `Tooltip.Trigger` should be a real button, link, or input - not a `<div>`.

A tooltip is supplementary. It can clarify a control, but it cannot be the only place a piece of
information lives - a touch user never sees it, and a screen-reader user hears it only as a
description. An icon-only button still needs its own `aria-label`; the tooltip repeats that name
for sighted pointer users, it does not replace it.
