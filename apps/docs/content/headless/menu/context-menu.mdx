# ContextMenu

<Lede>
  ContextMenu is a Menu summoned by a right-click. It opens at the pointer's coordinates and shares
  Menu's keyboard model exactly - only the trigger differs.
</Lede>

<ComponentDemoStrip demo="context-menu" />

<ArticleMeta />

## What it is

A compound component whose trigger is a region rather than a button. A right-click - the
`contextmenu` event - opens the panel at the cursor. From there it behaves like
[Menu](/headless/menu/menu): `role="menu"`, `role="menuitem"` rows, arrow-key navigation, Escape
to close.

ContextMenu has no `Trigger`-as-button. The `ContextMenu.Trigger` wraps a region, and the menu's
position comes from the click coordinates, not from a `placement` prop.

## Install

<CodeBlock lang="bash" code={`yarn add @usemotif/headless`} />

<CodeBlock lang="tsx" code={`import { ContextMenu } from '@usemotif/headless';`} />

## Anatomy

<CodeBlock lang="tsx" code={`<ContextMenu.Root>

On a touch screen the trigger also opens on a long-press: a touch held for `longPressDelay`
(500 ms by default, React Native's long-press delay) opens the menu at the finger. Moving more
than 10 px, lifting, or the browser cancelling the touch stops it, and the click a browser may
send on release is swallowed. iOS Safari shows its own callout and starts a text selection on
a long-press; turn those off on the trigger element with
`style={{ WebkitTouchCallout: 'none', userSelect: 'none' }}`.

### ContextMenu.Item

The same component as [Menu.Item](/headless/menu/menu#menuitem) - `onSelect`, `disabled`,
`style`, `asChild`, `children`. Activation closes the menu.

### ContextMenu.Sub, ContextMenu.SubTrigger, ContextMenu.SubContent

The same submenu parts as [Menu.Sub](/headless/menu/menu#menusub-menusubtrigger-menusubcontent),
with the same keyboard and pointer behaviour.

<CodeBlock lang="tsx" code={`<ContextMenu.Sub>
  <ContextMenu.SubTrigger>Move to</ContextMenu.SubTrigger>
  <ContextMenu.SubContent>
    <ContextMenu.Item onSelect={archive}>Archive</ContextMenu.Item>
  </ContextMenu.SubContent>
</ContextMenu.Sub>`} />

## Accessibility

ContextMenu carries the same ARIA as Menu - `role="menu"`, `role="menuitem"`, `aria-disabled` on
disabled rows. Opening the menu focuses the first enabled item; the arrow keys, Home, End, and
Escape all behave as they do in Menu.

A right-click or long-press is a pointer-only gesture. Whatever a ContextMenu offers must also be
reachable another way - a visible [Menu](/headless/menu/menu) button, a toolbar, a keyboard shortcut - so
keyboard and touch users are not locked out of the actions.

## Examples

A right-click menu on a file row:

<CodeBlock lang="tsx" code={`<ContextMenu.Root>
  <ContextMenu.Trigger>
    <Box p="$2" borderRadius="$radii.sm">{file.name}</Box>
  </ContextMenu.Trigger>
  <ContextMenu.Content style={{ padding: 4, background: 'var(--colors-surface-base)' }}>
    <ContextMenu.Item onSelect={() => rename(file)}>Rename</ContextMenu.Item>
    <ContextMenu.Item onSelect={() => download(file)}>Download</ContextMenu.Item>
    <ContextMenu.Item onSelect={() => remove(file)}>Delete</ContextMenu.Item>
  </ContextMenu.Content>
</ContextMenu.Root>`} />
