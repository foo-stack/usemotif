# Migrate

`@usemotif/migrate` ships the codemods that rewrite import specifiers across motif's version
boundaries (`rename-v2` and `rename-v3`), and two that move code over from another library
(`from-styled-components` and `from-tamagui`). The CLI is the primary surface for end users. The Node API is exported for anyone wiring the same transforms
into their own codemod pipeline.

<ArticleMeta />

## CLI

The shortest path. Run via `npx`:

<CodeBlock lang="bash" code={`# Rewrite v1 imports to v2 names (legacy two-step path).
npx @usemotif/migrate rename-v2 src/

# Rewrite v1 or v2 imports to v3 names in one pass.
npx @usemotif/migrate rename-v3 src/

# Dry-run - print the rewrites without touching files.
npx @usemotif/migrate rename-v3 --dry-run src/`} />

Both transforms walk `.ts`, `.tsx`, `.js`, `.jsx`, `.mdx`, and `.json` files. The transforms
are idempotent - running them twice produces no further changes.

`rename-v3` is the recommended path for everyone migrating to the `@usemotif/*` scope. The
intermediate `rename-v2` transform is preserved for anyone who wants to do the two-step
migration deliberately (v1 → v2 → v3), or for tooling that needs to address the v1 → v2
rename specifically.

## Migrating from another library

<CodeBlock lang="bash" code={`npx @usemotif/migrate from-styled-components src/
npx @usemotif/migrate from-tamagui src/`} />

Both parse each `.js`, `.jsx`, `.ts` and `.tsx` file and edit it in place, so the rest of the file
keeps its formatting. What they convert:

| Command | Converts |
| --- | --- |
| `from-styled-components` | `styled.div` and `styled(Component)` templates with no interpolations become `styled('div', { base: { ... } })`. `&:hover`, `&:focus`, `&:focus-visible`, `&:active`, `&:disabled`, `&::before` and `&::after` become state props. |
| `from-tamagui` | Imports with a motif counterpart move to `usemotif` (`XStack` becomes `HStack`, `Stack` becomes `Box`, `AnimatePresence` becomes `Presence`), and their uses follow. `hoverStyle`, `pressStyle`, `focusStyle` and `disabledStyle` become `_hover`, `_active`, `_focus` and `_disabled`. A `styled()` config's style props move into `base`. |

Anything they can't convert stays as it was, under a comment that says why:

<CodeBlock lang="tsx" code={`// usemotif-migrate: interpolations: express them as variants or tokens
const Button = styled.button\`
  color: \${(p) => p.color};
\`;`} />

Each changed file reports how many it left, and a second run adds nothing. Search for
`usemotif-migrate:` to finish the job. When some styled-components templates are left, the
converted ones use `motifStyled`, so the two libraries run side by side until the rest are done.

Neither rewrites token paths: Tamagui's `$4` and styled-components' `props.theme` read a different
theme, which you rebuild with `createTheme`. `from-tamagui` renames references by name rather than
by scope, so a local variable that shadows an imported component is renamed too.

## Node API

For programmatic use - e.g. an `npm run codemod` script that runs additional steps before or
after the rename.

### `applyRenameV3`

<ApiSignature

  params={[

      name: 'source',

    },
  ]}
/>

### `needsRenameV3`

<ApiSignature
  name="needsRenameV3"
  status="stable"
  signature={`function needsRenameV3(source: string): boolean`}
/>

Cheap check - returns `true` if the source would be modified by `applyRenameV3`. Use to skip
files quickly when walking a large tree.

### `applyRenameV2` / `needsRenameV2`

Same shape as the v3 pair, targeting the v1 → v2 rename. Preserved for tooling that needs to
address that boundary specifically.

## Example: scripted run

<CodeBlock lang="ts" filename="scripts/rename-imports.ts" code={`import { readFile, writeFile } from 'node:fs/promises';
import { globby } from 'globby';
import { applyRenameV3, needsRenameV3 } from '@usemotif/migrate';

const files = await globby(['src/**/*.{ts,tsx,js,jsx,mdx}']);

for (const file of files) {
  const source = await readFile(file, 'utf8');
  if (!needsRenameV3(source)) continue;
  await writeFile(file, applyRenameV3(source), 'utf8');
}`} />

The cheap check + read-when-needed pattern matters on large repos. `needsRenameV3` only scans
for the legacy specifier strings; `applyRenameV3` parses the AST.

## What gets rewritten

- ESM imports: `import { X } from '@motif-js/react'` → `import { X } from '@usemotif/react'`.
- Type-only imports.
- Namespace imports.
- Dynamic imports: `await import('@motif-js/react/server')`.
- CommonJS requires: `require('@motif-js/react')`.
- Re-exports: `export { X } from '@motif-js/react'`.
- `package.json` workspace dep keys.
- MDX import statements at the top of doc pages.

Sub-path specifiers are preserved - `@motif-js/react/server` becomes `@usemotif/react/server`.

## What does not get rewritten

- String literals that contain a package name but are not import-shaped. The codemod walks the
  AST, not raw text.
- Compiler allow-lists (`@usemotif/compiler-*` plugin options). Most plugins recognise both
  scoped names by default; check your bundler config if a specific allow-list was set.
- Historical references in `/migrating/*` doc pages or git history.
