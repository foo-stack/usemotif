## Description

Builds a regular React component that resolves variant props, merges the matching style bags onto
`base`, and renders `Component` with the result. Caller-supplied style props always override the
variant-derived defaults - a one-off tweak does not need a new variant.

The merge order, from lowest to highest priority:

1. `base`
2. Each active variant (explicit lookup; fallback function if the lookup misses)
3. Each `compoundVariants` entry whose matchers all match
4. Caller props

On web, if `Component` is a string, the result renders through `<Box as={Component}>` so style props
go through the standard pipeline.

<Callout variant="warning" title="String element types are web-only">
  There is no native `button` or `span`, so on React Native a string tag is dropped and the
  component renders as a plain `<View>` - with no press handling and no accessibility role. Styles
  and variants still resolve normally; only the element type is lost. Shared cross-platform code
  should pass a component instead: `styled(Pressable, ...)`, `styled(Text, ...)`, or `styled(Box, ...)`.
  A development-only console warning fires the first time each string tag is used on native.
</Callout>

## StyledConfig

<CodeBlock lang="ts" code={`interface StyledConfig<V extends AnyVariants = AnyVariants> {
  base?: StyleProps;
  variants?: V;
  compoundVariants?: readonly CompoundVariant<V>[];
  defaultVariants?: { [K in keyof V]?: keyof V[K] };
  context?: StyledContext<Record<string, unknown>>;
}`} />

- **`base`** - style props always applied.
- **`variants`** - named groups of style overrides. Two forms can coexist for the same axis:
  - **Explicit:** `size: { sm: { p: '$2' }, md: { p: '$4' } }`. The matching prop accepts only the
    listed keys (or `boolean` if the keys are `'true'` / `'false'`).
  - **Fallback:** `'...size': (val, ctx) => ({ p: val })`. The variant name is the key with the
    `...` prefix stripped. Any value the caller passes flows through the fallback. The optional
    second argument is a [`VariantContext`](#variantcontext) carrying the active theme/tokens and
    the component's props.
- **`compoundVariants`** - array of matchers plus a `css` bag. Applies when every matcher matches.
  Matchers can only target explicit variants - fallback values are open and not addressable.
- **`defaultVariants`** - values used when the caller does not specify the prop. Only explicit
  variants can have defaults.
- **`context`** - a [`StyledContext`](#createstyledcontext) from `createStyledContext`. The
  component reads inherited variant values from it and re-provides the merged result to its
  subtree, so a parent's variant flows to sub-components without prop threading.

## VariantProps

<CodeBlock lang="ts" code={`type ButtonVariants = VariantProps<typeof Button>; // from the component
type SizeOnly = VariantProps<typeof config.variants>; // or from the config`} />

The variant props of a `styled()` component, from the component itself or from its `variants`
config. Each variant name becomes one optional prop typed as the union of its explicit keys and
its fallback value type, in any of the responsive forms below.

`<Component size="sm" />` - `size` is keyof the explicit map; type-checked.

### Responsive variant values

A variant prop takes one value per breakpoint, in the same three syntaxes as a style prop:

<CodeBlock lang="tsx" code={`<Button size={{ base: 'sm', md: 'lg' }} />
<Button size={['sm', null, 'lg']} />
<Button size="base:sm md:lg" />`} />

The component resolves its variants once per breakpoint the value names, so compound variants
match per breakpoint too, and folds the results into responsive style props: `size` above becomes
`px={{ base: 2, md: 4 }}` and the like, state bags included. Keys that are not style props, such
as `transition`, come from the base value. A style that the smaller breakpoint's value sets and
the larger one's does not carries up, since CSS has no per-breakpoint unset. On React Native the
value resolves at the current viewport and container width, as style props do.

## CompoundVariant

<CodeBlock lang="ts" code={`type CompoundVariant<V extends AnyVariants> = {
  [K in keyof V as V[K] extends ExplicitVariant ? K : never]?: keyof V[K];
} & {
  css: StyleProps;
};`} />

One entry in the `compoundVariants` array: a partial match against explicit variants, plus a `css`
bag applied when every matcher is satisfied.

## VariantContext

<CodeBlock lang="ts" code={`interface VariantContext {
  theme: Theme | undefined;
  tokens: Theme['tokens'] | undefined;
  props: Readonly<Record<string, unknown>>;
}`} />

The optional second argument to a fallback-variant function. `theme` and `tokens` are `undefined`
outside a `ThemeProvider`, so a fallback that only returns `$`-token references needs no guard; the
context exists for fallbacks that must compute from a resolved token value or branch on a sibling
prop. Annotate the parameter explicitly (`(val, ctx: VariantContext) => ...`) - motif keeps this
typing local rather than registering a global config type.

## createStyledContext

<ApiSignature
  name="createStyledContext"
  status="stable"
  signature={`function createStyledContext<T extends Record<string, unknown>>(
  defaults: T,
): StyledContext<T>`}
  params={[
    {
      name: 'defaults',
      type: 'T',
      required: true,
      description:
        'The default variant values, used when no provider is above in the tree. The keys are the variant names that propagate.',
    },
  ]}
/>

Creates a styled context that carries a set of variant values from a parent `styled` component to
its descendants. Pass the returned object as the `context` field of every participating component.
Each such component reads the inherited values - filling in any variant the caller omitted - and
re-provides the merged result, so a `Button` frame's `size` reaches its `Text` and `Icon` without
prop threading. Precedence per key: the component's own `defaultVariants` < the inherited context
value < an explicit caller prop.

<CodeBlock lang="tsx" code={`import { styled, createStyledContext } from 'usemotif';

const ButtonContext = createStyledContext({ size: 'md' });

const Frame = styled('button', {
  context: ButtonContext,
  variants: { size: { sm: { height: 28 }, md: { height: 36 }, lg: { height: 44 } } },
  defaultVariants: { size: 'md' },
});
const Label = styled('span', {
  context: ButtonContext,
  variants: { size: { sm: { fontSize: 14 }, md: { fontSize: 16 }, lg: { fontSize: 20 } } },
});

// Label inherits size="lg" from the Frame - no prop threading.
<Frame size="lg">
  <Label>Save</Label>
</Frame>;`} />

## styledSlots

`styledSlots(config)` styles several named parts of one component from a single config, and
returns a `styled` component per slot. Every bag in the config is keyed by slot, and the slots
share their variants:

<CodeBlock lang="tsx" code={`import { styledSlots } from 'usemotif';

const Card = styledSlots({
  slots: { root: 'article', title: 'h3', body: 'div' },
  base: {
    root: { borderRadius: '$lg', p: '$4', bg: '$colors.surface.raised' },
    title: { fontWeight: '$semibold' },
  },
  variants: {
    size: {
      sm: { root: { p: '$3' }, title: { fontSize: '$md' } },
      lg: { root: { p: '$6' }, title: { fontSize: '$xl' } },
    },
  },
  compoundVariants: [{ size: 'lg', css: { body: { lineHeight: '$relaxed' } } }],
  defaultVariants: { size: 'sm' },
});

<Card.root size="lg">
  <Card.title>Plans</Card.title>
  <Card.body>Pick one.</Card.body>
</Card.root>`} />

| Field | Shape |
| --- | --- |
| `slots` | The element or component each slot renders: `{ root: 'article', title: Text }`. |
| `base` | A style bag per slot. |
| `variants` | `{ name: { value: { slot: bag } } }`. A value may style any of the slots. |
| `compoundVariants` | Matchers plus `css`, a bag per slot. |
| `defaultVariants` | One default per variant, shared by every slot. |

A variant set on one slot reaches every slot rendered inside it, through a styled context the
recipe creates, so `size` on the root sizes the title and body with no prop threading. A slot can
still take its own value, which then flows to the slots inside it. Each slot is an ordinary
`styled` component, typed the same way, and the recipe works the same on web and React Native.

## Example

<CodeBlock lang="tsx" code={`import { styled, Pressable } from 'usemotif';

const Button = styled(Pressable, {
  base: {
    display: 'inline-flex',
    alignItems: 'center',
    borderRadius: '$radii.md',
    transition: { property: 'background-color', duration: '$durations.2' },
  },
  variants: {
    intent: {
      primary: { bg: '$colors.action.primary.bg', color: '$colors.action.primary.fg' },
      neutral: { bg: '$colors.surface.muted', color: '$colors.text.default' },
    },
    size: {
      sm: { paddingBlock: '$space.1', paddingInline: '$space.3' },
      md: { paddingBlock: '$space.2', paddingInline: '$space.4' },
      lg: { paddingBlock: '$space.3', paddingInline: '$space.6' },
    },
  },
  compoundVariants: [
    { intent: 'primary', size: 'lg', css: { fontWeight: '$fontWeights.semibold' } },
  ],
  defaultVariants: { intent: 'neutral', size: 'md' },
});

<Button intent="primary" size="lg">
  Save
</Button>;`} />
