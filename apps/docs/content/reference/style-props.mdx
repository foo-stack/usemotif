# Style props

The exhaustive catalogue. Every primitive - `Box`, `Stack`, `Pressable`, `Text`, the typography
suite, `styled()` outputs - accepts the props listed here. Concept-level discussion lives on
[Style props](/concepts/style-props); this page is the lookup.

<ArticleMeta />

## CSS property props

Every CSS property motif resolves through is exposed as a prop. Names line up with the
camelCase JS form (`backgroundColor`, `paddingInline`, `gridTemplateColumns`). The full set is
exported from `@usemotif/core` as `STYLE_PROP_NAMES`.

<CodeBlock lang="ts" code={`import { STYLE_PROP_NAMES, isStyleProp, styleProps } from '@usemotif/core';

STYLE_PROP_NAMES.length;  // ~250
isStyleProp('backgroundColor');  // true
styleProps['backgroundColor'];   // { property: 'background-color', category: 'color', ... }`} />

`styleProps` is a map from prop name to its definition (`StylePropDefinition`). The definition
carries the CSS property it serialises to, the value category (`color`, `length`, `keyword`,
...), and whether the prop is responsive-eligible.

### Gradients

`backgroundImage` reads a theme's `gradients` scale, so a gradient defined once is a token like
any other, and `$gradients.` paths autocomplete on that prop:

<CodeBlock lang="tsx" code={`const theme = createTheme({
  name: 'brand',
  tokens: { gradients: { hero: 'linear-gradient(90deg, #2563eb, #7c3aed)' } },
});

<Box backgroundImage="$gradients.hero" p="$4" />`} />

It is web-only by design: React Native views have no background image, so native accepts the prop
for parity and draws nothing.

## Shorthand props

A small set of single-letter and two-letter aliases. Stable across releases.

| Prop | Maps to |
| --- | --- |
| `bg` | `backgroundColor` |
| `m` | `margin` |
| `mt` / `mb` / `ml` / `mr` | `marginTop` / `marginBottom` / `marginLeft` / `marginRight` |
| `mx` | `marginInline` |
| `ms` / `me` | `marginInlineStart` / `marginInlineEnd` |
| `my` | `marginBlock` |
| `p` | `padding` |
| `pt` / `pb` / `pl` / `pr` | `paddingTop` / `paddingBottom` / `paddingLeft` / `paddingRight` |
| `px` | `paddingInline` |
| `ps` / `pe` | `paddingInlineStart` / `paddingInlineEnd` |
| `py` | `paddingBlock` |
| `start` / `end` | `insetInlineStart` / `insetInlineEnd` |
| `w` | `width` |
| `h` | `height` |
| `minW` / `minH` | `minWidth` / `minHeight` |
| `maxW` / `maxH` | `maxWidth` / `maxHeight` |

`px` / `mx`, the `ps` / `pe` / `ms` / `me` shorthands, and the `start` / `end` insets are
**logical** - they resolve relative to the writing direction, so a layout mirrors correctly
under RTL. The physical `pl` / `pr` / `ml` / `mr` aliases are kept as an explicit escape hatch.
See [`Direction`](/reference/direction) for setting the writing direction of a subtree.

## Pseudo-state props

Style bags applied when a pseudo-class or ARIA state is true. Fourteen states are exposed.

<CodeBlock lang="ts" code={`import { PSEUDO_STATE_PROP_NAMES } from '@usemotif/core';

PSEUDO_STATE_PROP_NAMES;
// ['_hover', '_focus', '_active', '_disabled', '_checked', '_selected', '_expanded',
//  '_invalid', '_pressed', '_focusWithin', '_readOnly',
//  '_groupHover', '_groupFocus', '_groupActive'] as const`} />

| Prop | Pseudo |
| --- | --- |
| `_hover` | `:hover` (web only; no-op on touch surfaces) |
| `_focus` | `:focus-visible` |
| `_active` | `:active` (web) / pressed state (native via `Pressable`) |
| `_disabled` | `:disabled`, `[aria-disabled="true"]` |
| `_checked` | `:checked`, `[aria-checked="true"]` (checkbox / switch / radio) |
| `_selected` | `[aria-selected="true"]` (active tab / listbox option) |
| `_expanded` | `[aria-expanded="true"]` (open accordion / collapsible / popover trigger) |
| `_invalid` | `[aria-invalid="true"]` (a field that failed validation) |
| `_pressed` | `[aria-pressed="true"]` (a toggle button that is on) |
| `_focusWithin` | `:focus-within` (focus is on the element or inside it) |
| `_readOnly` | `[readonly]`, `[aria-readonly="true"]` |
| `_groupHover` | an ancestor Box with `group` is hovered |
| `_groupFocus` | an ancestor Box with `group` has `:focus-visible` |
| `_groupActive` | an ancestor Box with `group` is `:active` |

On web, the runtime emits one CSS rule per unique pseudo-state bag, hashed into a class. On
native, the bags drive `Pressable`'s state callbacks. `_checked` / `_selected` / `_expanded` cover
the interactive ARIA states form and composite-widget elements expose - so a styled toggle, tab, or
disclosure trigger can react to its own checked / selected / open state in pure CSS, with no JS.

Two of the newer states read attributes on purpose. `_invalid` is `[aria-invalid]` rather than
`:invalid`, which matches an empty required field before anyone has typed in it, and `_readOnly` is
the `readonly` attribute rather than `:read-only`, which matches every element that is not
editable. `_pressed` is a toggle's on state; a pointer held down is `_active`. On native, Box
ignores these four, as it does `_checked`, `_selected` and `_expanded`.

### Group states

Set `group` on a Box and its descendants can react to its state. The group renders a
`data-motif-group` attribute, and `_groupHover` and its peers key on it:

<CodeBlock lang="tsx" code={`<Box group p="$4" borderRadius="$lg" bg="$colors.surface.raised">
  <Text>Release notes</Text>
  <Text color="$colors.text.muted" _groupHover={{ color: '$colors.action.primary.bg' }}>
    Read more
  </Text>
</Box>
// [data-motif-group]:hover .m-x { color: var(--colors-action-primary-bg); }`} />

Any marked ancestor counts, so in nested groups the state of an outer group reaches an inner
child too. The group states are web-only for now: React Native ignores `group` and the three
props. The compiler extracts a child's group states, and leaves a `group` Box in place so its
marker attribute is rendered.

### Responsive values inside a state

A value inside a state bag can be responsive, in any of the three syntaxes. On the web the
breakpoint or container query nests around the state selector:

<CodeBlock lang="tsx" code={`<Box
  bg="$colors.surface.raised"
  _hover={{ bg: { base: '$colors.surface.muted', md: '$colors.surface.interactive' } }}
/>
// .m-x:hover { background-color: var(--colors-surface-muted); }
// @media (min-width: 768px) { .m-x:hover { background-color: var(--colors-surface-interactive); } }`} />

The compiler extracts these the same way, to the same class. On React Native, `Pressable` resolves
a state bag at the current viewport and container width, as it does its other props.

## Pseudo-element props

Style bags applied to generated content. Two pseudo-elements are exposed.

<CodeBlock lang="ts" code={`import { PSEUDO_ELEMENT_PROP_NAMES } from '@usemotif/core';

PSEUDO_ELEMENT_PROP_NAMES;
// ['_before', '_after'] as const`} />

| Prop | Pseudo-element |
| --- | --- |
| `_before` | `::before` |
| `_after` | `::after` |

Both are web-only - native has no analogue. The bag accepts every CSS property, plus the
required `content` property when generating a pseudo-element.

<CodeBlock lang="tsx" code={`<Box
  _before={{ content: '"›"', mr: '$space.2', color: '$colors.text.muted' }}
/>`} />

## Motion props

Animation and transition props plus enter/exit hooks for unmount animations.

<CodeBlock lang="ts" code={`import { MOTION_PROP_NAMES } from '@usemotif/core';

MOTION_PROP_NAMES;
// ['enterStyle', 'exitStyle', 'transition', 'animation', 'animateOnly'] as const`} />

| Prop | Purpose |
| --- | --- |
| `transition` | CSS-transition spec. Accepts `{ property, duration, easing, delay }` or a `'$transitions.<name>'` reference. |
| `animation` | Named keyframe animation. Accepts `{ name, duration, easing, ... }` where `name` is a `Keyframe` from [`keyframes`](/reference/keyframes) or a `'$animations.<name>'` reference. |
| `enterStyle` | Initial style on mount. The component renders with this style then transitions to its resting state, timed by `transition`. |
| `exitStyle` | Final style on unmount. The component transitions to this style before being removed. May carry its own `transition` to time the exit independently of the enter. |
| `animateOnly` | Allow-list of style props to animate. Other style changes apply instantly. |

Motion values resolve through the same token pipeline as colour and spacing. `transition: { duration: '$durations.2' }` is first-class.

### Asymmetric enter / exit

`transition` times the enter (and ordinary prop changes); a `transition` placed _inside_ `exitStyle`
overrides it for the exiting phase only. This is how you get the common "fade in fast, fade out slow"
shape without two components:

<CodeBlock lang="tsx" code={`<Box
  transition={{ property: 'opacity', duration: '$durations.2' }}      // enter: quick
  enterStyle={{ opacity: 0 }}
  exitStyle={{ opacity: 0, transition: { property: 'opacity', duration: '$durations.5', easing: 'ease-in' } }} // exit: slow
/>`} />

The exit transition is emitted as the `[data-motif-state="exiting"]` rule and the base `transition`
is lifted to a class so the exit rule wins the cascade - no inline-specificity surprises. When an
exit-aware boundary ([`Dialog`](/headless/overlay/dialog), [`Drawer`](/headless/overlay/drawer))
manages unmount, make sure its `fallbackDurationMs` is at least the exit duration so the element
isn't pulled before the animation finishes.

### Layout animation

`layout` is a Box prop rather than a style prop: set it and a change to the Box's position or size
between renders animates instead of jumping (`'position'` or `'size'` limits it to one). It runs
300ms ease-in-out unless `layoutTransition` says otherwise, with the same value forms as
`transition`:

<CodeBlock lang="tsx" code={`<Box layout layoutTransition={{ duration: '$durations.5', easing: '$easings.decelerate' }}>
  {expanded ? <Details /> : <Summary />}
</Box>`} />

On the web the tokens become CSS variables, so a theme switch retimes the animation. On React
Native they resolve against the active theme, and `cubic-bezier(...)` easings map to RN's
`Easing.bezier`. The compiler leaves a Box with any of these props in place, since the animation
runs in the runtime component.

`layoutId` shares one layout between two Boxes: when a Box with the id unmounts and another with
the same id mounts, the new one animates from the old one's position and size. See
[shared layout transitions](/recipes/animation-patterns#shared-layout-transitions).

## Container query prop

`_container` declares a container-query block. The keys are container-query syntax (`'@container (min-width: 480px)'`); the values are style bags.

<CodeBlock lang="tsx" code={`<Box
  containerType="inline-size"
  _container={{
    '@container (min-width: 480px)': { p: '$space.6', fontSize: '$fontSizes.lg' },
  }}
/>`} />

The `containerType` (or `containerName`) prop turns the element into a query container; the
`_container` prop responds inside it. See [Responsive](/concepts/responsive) for the full
container-query model and the available syntactic forms.

## Helpers exported from `@usemotif/core`

For tooling and runtime-introspection use cases.

<CodeBlock lang="ts" code={`import {
  isStyleProp,
  isMotionProp,
  isPseudoStateProp,
  isPseudoElementProp,
  STYLE_PROP_NAMES,
  PSEUDO_STATE_PROPS,
  PSEUDO_ELEMENT_PROPS,
  MOTION_PROPS,
  styleProps,
} from '@usemotif/core';`} />

| Symbol | Shape | Purpose |
| --- | --- | --- |
| `STYLE_PROP_NAMES` | `readonly string[]` | The full list of supported CSS-property prop names, in stable order. |
| `styleProps` | `Record<string, StylePropDefinition>` | Map from prop name to its definition (target CSS property, category, responsive eligibility). |
| `isStyleProp(name)` | `(string) => boolean` | Membership check against the catalogue. |
| `PSEUDO_STATE_PROPS` | `ReadonlySet<string>` | Set for fast membership checks. |
| `PSEUDO_ELEMENT_PROPS` | `ReadonlySet<string>` | Same, pseudo-elements. |
| `MOTION_PROPS` | `ReadonlySet<string>` | Same, motion. |
| `isPseudoStateProp(name)` / `isPseudoElementProp(name)` / `isMotionProp(name)` | `(string) => boolean` | Targeted membership checks. |

Compiler plugins consume these to classify JSX attributes during static extraction. Application
code rarely needs them.
