# Tokens

The `@usemotif/tokens` package ships four ready-to-use themes (light, dark, and a high-contrast
variant of each) and the sixteen primitive scales
they are built from. Reach for it when you want a working design system today; build your own
with [`createTheme`](/reference/create-theme) when you want full ownership of the values.

## Themes

  name="lightTheme"
  status="stable"
  signature={`const lightTheme: Theme`}
/>

<ApiSignature
  name="darkTheme"
  status="stable"
  signature={`const darkTheme: Theme`}
/>

Both themes share the same semantic surface (`surface.base`, `surface.muted`, `text.default`,
`action.primary.bg`, ...) and the same primitive scales. They differ in which primitive each
semantic path resolves to - that is the whole story of light-vs-dark in this token set.

One entry in the `surface` group is worth calling out for theme authors: `surface.interactive`
is the hover / highlight fill for rows and triggers sitting on a panel - menu items, listbox
options, calendar days. `@usemotif/ui` styles those states with it, so a hand-authored theme
that omits it renders those components with no hover state at all. It is deliberately not a
reuse of `surface.muted`: a panel is `raised`, and in the dark theme `raised` and `muted` land
on the same primitive, so a hover painted with `muted` would be invisible there.

Two color groups carry intent. `action.{primary,danger,success,neutral}` is for solid controls -
`{ bg, fg, hover }`, where `fg` reads on the filled `bg`. `neutral` lives here rather than being
read off the `gray` ramp because a primitive ramp resolves to the same literal in every theme:
a neutral control wired to `gray.200`/`gray.900` would keep light-mode colours on a dark canvas.
`status.{neutral,info,success,warning,danger}`
is for soft feedback surfaces (alerts, badges, banners) - `{ tint, fg, border }`, where `tint`
is a subtle background and `fg` reads on the tint. Light mode uses the `50`/`700`/`200` shades;
dark mode inverts to `950`/`300`/`800`.

<CodeBlock lang="tsx" code={`import { ThemeProvider } from 'usemotif';
import { lightTheme, darkTheme } from '@usemotif/tokens';

<ThemeProvider themes={[lightTheme, darkTheme]} active="light">
  {children}
</ThemeProvider>`} />

### High contrast

  name="highContrastLightTheme"
  status="stable"
  signature={`const highContrastLightTheme: Theme`}
/>

<ApiSignature
  name="highContrastDarkTheme"
  status="stable"
  signature={`const highContrastDarkTheme: Theme`}
/>

The same semantic surface again, rebound for users who need stronger contrast. Every text
colour reaches 7:1 (WCAG AAA) on every surface, every solid control's label reaches 7:1 on its
fill and hover fill, every status text reaches 7:1 on its tint, and every border reaches 3:1 on
the surfaces it sits on. A test in `@usemotif/tokens` resolves each of those pairs to its
colour and fails if any falls short. Both are built only from the shared palette, so they mix
with the default presets: register them alongside and switch with `active`.

<CodeBlock lang="tsx" code={`import {
  darkTheme,
  highContrastDarkTheme,
  highContrastLightTheme,
  lightTheme,
} from '@usemotif/tokens';

<ThemeProvider
  themes={[lightTheme, darkTheme, highContrastLightTheme, highContrastDarkTheme]}
  active="high-contrast-light"
>
  {children}
</ThemeProvider>`} />

## Primitive scales

Each scale is exported individually so you can compose a custom theme that reuses the motif
defaults selectively.

<CodeBlock lang="ts" code={`import {
  animations,
  borderWidths,
  colors,
  durations,
  easings,
  fontFamilies,
  fontSizes,
  fontWeights,
  letterSpacings,
  lineHeights,
  opacities,
  radii,
  shadows,
  sizes,
  space,
  zIndices,
} from '@usemotif/tokens';`} />

| Scale | Shape | Notes |
| --- | --- | --- |
| `colors` | `Record<string, string \| Record<string, string>>` | Hex codes plus the palette ramps (`blue.50` ... `blue.900`). |
| `space` | `Record<number \| string, number>` | Numeric scale (`0` ... `40` in pixels) plus named extras. |
| `sizes` | `Record<string, number \| string>` | Width / height defaults - `xs` ... `7xl`, plus `full` / `screen`. |
| `radii` | `Record<string, number \| string>` | Border-radius scale: `none`, `sm`, `md`, `lg`, `xl`, `full`. |
| `borderWidths` | `Record<string, number>` | Border-width scale: `none`, `hairline`, `thin`, `thick`. |
| `fontFamilies` | `Record<string, string>` | Stack strings: `sans`, `serif`, `mono`, `display`. |
| `fontSizes` | `Record<string, number>` | Type scale: `xs` ... `7xl` in pixels. |
| `fontWeights` | `Record<string, number>` | `100` ... `900` plus named aliases (`regular`, `medium`, `semibold`, ...). |
| `lineHeights` | `Record<string, number \| string>` | Numeric ratios + named (`tight`, `snug`, ...). |
| `letterSpacings` | `Record<string, number>` | Tracking scale: `tighter`, `tight`, `normal`, `wide`. |
| `shadows` | `Record<string, string>` | `sm` ... `2xl` plus `inner` / `none`. |
| `durations` | `Record<string \| number, string>` | Millisecond strings used by `transition` / `animation`. |
| `easings` | `Record<string, string>` | Named easings: `standard`, `decelerate`, `accelerate`, `emphasised`. |
| `opacities` | `Record<string, number>` | `0` to `100` in tens, plus semantic (`disabled`, `subtle`). |
| `zIndices` | `Record<string, number>` | Named layers: `hide`, `auto`, `base`, `docked`, `dropdown`, `sticky`, `banner`, `overlay`, `modal`, `popover`, `tooltip`, `toast`. |
| `animations` | `Record<string, AnimationToken>` | Reusable keyframe + timing pairs. |

## Composing your own theme

The presets are the typical case. When the design system demands different values, compose at
the scale level rather than reauthoring everything:

<CodeBlock lang="ts" code={`import { createTheme } from 'usemotif';
import { space, radii, fontSizes } from '@usemotif/tokens';

export const brandTheme = createTheme({
  name: 'brand',
  tokens: {
    space, radii, fontSizes,
    colors: {
      ink: '#0F172A',
      paper: '#FAFAF9',
      brand: { base: '#7C3AED', accent: '#EC4899' },
      surface: { base: '$colors.paper' },
      text: { default: '$colors.ink' },
      action: { primary: { bg: '$colors.brand.base', fg: '$colors.paper' } },
    },
  },
});`} />

`createTheme` does no transformation - the returned object is the input, with its literal token
shape preserved at the type level. `$`-references autocomplete against that shape once you
declare the theme; see [Token autocomplete](/guides/token-autocomplete).
